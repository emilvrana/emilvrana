The Tool Count Trap: Why More Tools Make Your Agent Worse

May 24, 2026

Every new agent project starts the same way: you connect a few tools, it works great, and you think "let me add more capabilities." A file system tool, a search tool, a database tool, three different APIs. Before long your agent has 25, 30, 40 tools — and somehow it's worse than when it had five.

I've built and maintained agent systems with tool counts ranging from 3 to 50+. The pattern is consistent: there's a sweet spot around 7–12 tools where the agent is reliable and fast. Below that, you're limiting what it can do. Above that, you're fighting tool confusion, wrong selections, and bloated context windows.

Why More Tools Hurt

1. The model has to choose from a longer list

Every tool call starts with a decision: which tool, which arguments. The more tools in the list, the more tokens the model spends on that decision — and the higher the chance it picks the wrong one. I've seen agents with 30+ tools consistently pick the second-best tool because the descriptions were similar and the model couldn't reliably distinguish them.

Tool selection accuracy isn't linear. With 5 tools, the model barely thinks about it. With 15, it's a conscious choice. With 30, it's guesswork dressed up as reasoning.

2. Schema bloat eats your context window

Each tool definition includes the name, description, and full parameter schema. In a system with 40 tools, tool definitions alone can consume 4,000–8,000 tokens before the agent even starts working. On models with smaller context windows, that's real money and real context that could've gone to the actual task.

More tools = larger prompt = more cost = less room for actual work.

3. Overlapping tools create ambiguity

When three tools can accomplish roughly the same thing, the agent wastes cycles deciding between them — and sometimes tries all three in sequence, burning tokens on redundant work. I had an agent with both search_web and search_docs tools that kept calling both for every query because it couldn't determine which was appropriate.

The Sweet Spot

After running many iterations, my rule of thumb:

  • 3–6 tools: Good for focused, single-purpose agents. Reliable, fast, predictable.
  • 7–12 tools: The sweet spot for general-purpose agents. Enough capability without decision overload.
  • 13–20 tools: You can make this work with careful descriptions and grouping, but accuracy starts dropping.
  • 20+ tools: Almost always a mistake. Time to split into specialized agents.

How to Reduce Your Tool Count

Merge overlapping tools

If you have search_web, search_news, and search_academic — merge them into one search tool with a type parameter. The model is much better at choosing parameter values than choosing between similar tools.

Use tool groups (or routers)

Instead of listing all tools at once, implement a two-stage approach: a router selects a tool group (web, file, database), then the agent gets only that group's tools. Most agent frameworks support this via dynamic tool lists.

Ask: does the agent actually use this?

Audit your tool usage logs. If a tool hasn't been called in the last 100 runs, remove it. Unused tools add noise and confusion. You can always add them back.

Split the agent

If you genuinely need 20+ tools, you probably need two agents. One that plans and one that executes. Or one for research and one for action. Splitting by responsibility almost always beats one agent doing everything poorly.

What I Actually Do

For my current production agents:

  • Research agent: 6 tools (search, read, write, memory, browser, evaluate)
  • Infrastructure agent: 8 tools (docker, ssh, logs, config, deploy, health, rollback, notify)
  • Communication agent: 5 tools (send, read, summarize, schedule, draft)

Each agent is focused, reliable, and fast. When I need multi-step work across domains, I route between agents — not between 30 tools inside one.

The Uncomfortable Truth

Adding a tool feels like adding a capability. In reality, you're adding a decision point, context overhead, and a potential failure mode. Every tool you remove is one less thing that can go wrong.

The best agent isn't the one with the most tools — it's the one that reliably picks the right tool for the job.

Count your tools. If the number is above 15, you have work to do. If it's above 25, you have a redesign to do. Cut, merge, group, or split — but don't just keep adding.
